# CriticalFlow AI - Synthetic IBM Z Incident Dataset (v1.0)

**3,000 synthetic job-completion events** (1-30 Sep 2026) in the CriticalFlow AI event contract v1.0.0,
plus training labels. **All data is synthetic**: no real customer, account or system data. Generated by
`generate_dataset.py` (seed 42, reproducible) and passed through `normalize_z_event.py`, so every row is
schema-valid against `criticalflow_event.schema.json`.

## Files
| File | Purpose |
|---|---|
| `training_data.csv` | Flat table for pandas/sklearn (snippet lines joined with ` \| `) |
| `training_data.jsonl` | Same rows as JSON lines (snippet keeps `\n`) |
| `criticalflow_event.schema.json` | Contract schema (labels are extra columns, not part of it) |
| `generate_dataset.py`, `normalize_z_event.py` | Regenerate: `python generate_dataset.py 3000 42` (needs `jsonschema`) |

## Columns
Contract fields: `schema_version, incident_id, timestamp, system_id, subsystem, job_name, job_id, step_name,
completion_status (CC|ABEND|JCL_ERROR), return_code, abend_code, primary_message_id, cpu_utilization_pct,
error_rate_pct, transaction_volume_per_hr, recent_deployment_flag, raw_log_snippet`.

Label columns:
| Column | Meaning |
|---|---|
| `scenario_type` | generator scenario: normal, warning, exhaustion, abend, jcl_error |
| `risk_score` | regression target, 0.01-0.99 |
| `risk_label` | LOW (<0.2), MEDIUM (0.2-0.55), HIGH (0.55-0.8), CRITICAL (>=0.8) |
| `is_high_risk` | binary target: HIGH or CRITICAL |
| `split` | `train` / `val` / `test` |

Nulls are meaningful: `return_code` is null unless `CC`; `abend_code` is null unless `ABEND`; metrics are null for
`JCL_ERROR` (job never ran) and for ~2% of other rows (metric feed missing). Treat as missing, not zero.

## Class balance
LOW 2165 (72%), MEDIUM 363, HIGH 239, CRITICAL 233. Status: CC 2721, ABEND 149, JCL_ERROR 130.
ABEND codes: S0C4, S806, S0C7, U0001, U4038, SB37, SD37, U0100, S222, S322.
Expect imbalance: use class weights, PR-AUC/macro-F1, not accuracy.

## Splits
Time-based to prevent leakage: oldest 70% train (1-22 Sep), next 15% val (22-26 Sep), newest 15% test (26-30 Sep).
Do not shuffle across splits.

## Known limitations (read before publishing results)
- `risk_label`/`risk_score` come from a rule-based generator with noise, so a model can partly re-learn those rules
  (especially from `completion_status`, `return_code`, `error_rate_pct`). Treat results as a pipeline test, not
  evidence of real-world accuracy. Replace with analyst-reviewed labels for production.
- `raw_log_snippet` contains the failure signature; drop it for tabular baselines, or use it for text/LLM experiments.
- Distributions (CPU, TPH, failure rates, deployment effect) are illustrative, not measured from real LPARs.
- Deployment flag raises abend probability by design (12% of jobs flagged).
